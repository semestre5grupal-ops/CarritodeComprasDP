# **TAREA 3 – RETO DE DESEMPEÑO ACADÉMICO (RDA 3\)**

## **1\. Contexto del reto**

En la Tarea 2 (RRD 2), el estudiante desarrolló una aplicación web con arquitectura cliente-servidor, implementando un CRUD funcional, consumo de API REST y una interfaz web básica.

En este RDA 3, el estudiante evoluciona ese mismo proyecto, manteniendo el backend previamente construido, pero reconstruyendo el frontend utilizando un framework moderno (Angular, React o Vue), e incorporando mecanismos reales de seguridad, pruebas, optimización y despliegue, alineados con prácticas profesionales de la industria del software.

Este reto integra los contenidos desde la Clase 12 hasta la Clase 16, culminando en un proyecto listo para producción.

## **2\. Objetivo general del reto**

Desarrollar y desplegar una aplicación web completa basada en arquitectura cliente-servidor, que implemente un CRUD seguro, con autenticación, pruebas, optimización, documentación técnica y despliegue en la nube, utilizando un framework front-end moderno (Angular, React o Vue) y un backend previamente implementado con API REST.

## **3\. Objetivos específicos**

Al finalizar el reto, el estudiante será capaz de:

1. Implementar un frontend moderno utilizando Angular, React o Vue.  
2. Integrar mecanismos de seguridad básica conforme a OWASP Top 10\.  
3. Consumir APIs REST usando Fetch, Axios o HttpClient.  
4. Implementar autenticación y autorización mediante JWT.  
5. Validar y sanitizar entradas del usuario.  
6. Realizar pruebas unitarias y análisis estático del código.  
7. Optimizar el rendimiento del frontend y del consumo de red.  
8. Desplegar la aplicación en un entorno de nube.  
9. Documentar técnica y funcionalmente el proyecto.  
10. Defender técnicamente la solución desarrollada.

## **4\. Alcance funcional mínimo (requisitos obligatorios)**

El proyecto debe cumplir todos los siguientes puntos:

### **4.1 Backend (continuación del proyecto previo)**

* API REST funcional con endpoints CRUD.  
* Autenticación mediante JWT.  
* Manejo de roles (al menos: admin / usuario).  
* Configuración correcta de CORS.  
* Validación y limpieza de datos de entrada.  
* Manejo básico de errores.

*(Se puede reutilizar el backend del Reto anterior, ajustándolo si es necesario.)*

### **4.2 Frontend (nuevo – obligatorio)**

El frontend DEBE desarrollarse exclusivamente con el framework asignado en el sorteo:

* Angular o  
* React o  
* Vue

El frontend debe incluir:

* Arquitectura por componentes.  
* Rutas protegidas (según autenticación).  
* Formularios conectados al backend.  
* Listado, creación, edición y eliminación de registros (CRUD completo).  
* Manejo de estado (state, services, composables o hooks).  
* Visualización clara de datos.  
* Manejo de errores y mensajes al usuario.  
* Diseño profesional usando Bootstrap u otro framework CSS.

## **5\. Contenidos académicos que deben evidenciarse**

El estudiante debe demostrar explícitamente el uso de los siguientes contenidos:

### **Clase 12 – Seguridad básica**

* Identificación de riesgos OWASP Top 10 (mínimo 3 explicados).  
* Uso de JWT.  
* Configuración correcta de CORS.  
* Manejo seguro de contraseñas.  
* Validación y sanitización de entradas.

### **Clase 13 – Integración cliente-servidor**

* Comunicación cliente-servidor con Fetch / Axios / HttpClient.  
* Envío y recepción de datos dinámicos.  
* Formularios conectados al backend.  
* Visualización de datos.  
* Pruebas del flujo CRUD completo.

### **Clase 14 – Pruebas y optimización**

* Uso de herramientas de depuración del navegador.  
* Pruebas unitarias (Jest u equivalente).  
* Análisis estático del código (ESLint).  
* Optimización de rendimiento.  
* Refactorización del código.  
* Documentación técnica.

### **Clase 15 – Despliegue y monitoreo**

* Despliegue en Render, Vercel o Netlify.  
* Uso de variables de entorno.  
* Publicación funcional de la aplicación.  
* Logging básico de errores.  
* Pruebas en entorno de producción.

### **Clase 16 – Proyecto final**

* Presentación estructurada del proyecto.  
* CRUD completo con autenticación.  
* Documentación técnica y de usuario.  
* Defensa del proyecto.  
* Reflexión final y lecciones aprendidas.

## **6\. Entregables obligatorios**

El estudiante debe entregar:

1. Repositorio Git (GitHub/GitLab) con:  
   * Backend  
   * Frontend  
   * Commits claros y progresivos  
2. URL de la aplicación desplegada (frontend).  
3. Documento PDF que incluya:  
   * Descripción general del sistema.  
   * Arquitectura utilizada.  
   * Evidencia de seguridad aplicada.  
   * Evidencia de pruebas realizadas.  
   * Capturas del despliegue.  
   * Reflexión final (lecciones aprendidas).  
4. Presentación oral (según el horario que indique el docente).

## **7\. Criterios generales de evaluación**

* Cumplimiento funcional del CRUD.  
* Uso correcto del framework asignado.  
* Integración real cliente-servidor.  
* Aplicación de seguridad básica.  
* Calidad del código y estructura.  
* Uso de pruebas y herramientas de análisis.  
* Despliegue exitoso.  
* Calidad de la documentación.  
* Claridad en la defensa del proyecto.

## **8\. Consideraciones finales**

* No se aceptarán proyectos sin framework moderno.  
* No se aceptarán proyectos sin despliegue.  
* El incumplimiento de requisitos mínimos invalida la entrega.  
* El proyecto debe demostrar autonomía técnica y comprensión conceptual, no solo funcionamiento.
